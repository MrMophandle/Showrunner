## What Plan H established that later plans build on

- **The console serves shows, plural.** A registry file `~/.showrunner/shows.json` (`{"shows": {"<key>": {"root": "<path>", "readOnly": true?}}}`) names each show by an operator-chosen key matching `/^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$/`; `--registry <file>` overrides the path; `--show <root>` is single mode (one show keyed by its directory's basename, nothing written) and cannot be combined with `--registry` (exit 64); an absent registry is an empty one and the server still starts; a malformed registry is fatal (exit 65); a show whose repository will not load is skipped and answered for — `GET /api/shows` and the SSE `hello` carry a `failed: {key, root, error}[]` list beside the nine-field `ShowInfo` rows and the Shows page draws each with its reason; `registerShow` takes an advisory `<file>.lock` (`wx`, a bounded wait, a refusal naming the file) around its read-and-write so two tabs or two consoles sharing the file cannot drop each other's entry; a registry edited by hand takes effect at the next start. One `ShowContext` and one `RunStore` per show; every API route sits under `/api/shows/:show/…` except the global `GET /api/events` (whose stream subscribes to a show's store the moment it is created and resends `hello`, so a show started from the form reaches an already-open channel) and the collection routes `GET /api/shows` and `POST /api/shows`; the middleware validates the key before any map or path and answers `404 {"error":"no such show"}` or, for every POST under a read-only show including unregistered paths, `403`. The slug keys nothing: the two real repositories share `showSlug DeadLight` and `output.nasRoot /Volumes/media/DeadLight`, which is why the retired one is registered `"readOnly": true` — one launch there would overwrite the live Season 1 finals.
- **The client knows which show it is looking at.** `/` lists the shows; `/shows/:show` is the Board; every link, fetch and title carries the key through one builder (`showPath`/`showHref`); the SSE parser drops any notice whose `show` is not a string and each page drops another show's notice before any refetch; a read-only show renders no Launch, Continue, New-episode form, Approve, Reject or action bar, one line naming the key and the NAS collision in their place, and its tab title never alerts.
- **The bible interview runs from the browser.** `/shows/new` is the New-show form over the tools' `initScaffold` plus `registerShow` (a path inside the engine root or inside or containing any registered root is refused; a duplicate key is 409; the server's maps gain the show without a restart). `/shows/:show/bible` draws the fifteen `BIBLE_FILES` rows with nine states derived from the row, `answers.md`, the latest setup log and the lock; `/shows/:show/bible/:key` is the question form, the running panel, the gate panel (Approve, Reject with notes, I will write it myself, Import, each posting `expectedAttempt`), the approved file, or the trouble panel; a Finish panel runs `initFinish` once every gated file is approved (409 with the unapproved keys otherwise). The interview's writing step runs in a detached setup worker (`console/worker/setup.ts`; `--show --key --run --engine-root --operator`; `--key` checked against `BIBLE_FILES` and `--run` against the run-id regex before any path or spawn; a lock beside the log, extracted into `console/worker/lock.ts` and shared with the episode worker); its gate is answered through the engine's `answerGate`; **the setup worker, not the server, calls `afterFileApproved` after its run completes**, so the approving commit carries the complete log and the show's `git status` is empty afterwards.
- **The tools' `init` is a library.** `@showrunner/tools` exports `initScaffold`, `afterFileApproved`, `initFinish`, `runInit`, `questionsFor`, `readAnswers`, `writeAnswers`, `buildVars`, `latestSetupLog`, `interviewPromptsDir`, `GATE_CHOICES`, `isApproved`, `resolveImport`, the cast-line parser and `IMPORT_NOTES_PREFIX` through `tools/src/index.ts` (`main` + `exports` in `tools/package.json`); the terminal `init` is recomposed from the same phases and its suites pass unchanged.
- **Two engine guards are stricter.** `missingRefs` refuses an outline whose `## Cast` section is absent or holds nothing parseable (`the outline has no readable ## Cast section (write one line per subject as "- <Name> (<tags>)")`), while an outline file that does not exist still reports nothing because `premise` owns that state; `parseCastSection` skips a whole-line HTML comment and ends the section at an ATX heading of any level (the shipped outline template carries both a comment and `### Beat` headings under `## Cast`, and both were reported as malformed cast lines until Task 8's fix round measured the real template); `loadShowConfig` validates `audio.guestRefsDir` at load through one exported `checkGuestRefsDir` that `needs.ts` also calls.
- **Smaller things.** `npm run dev` in `console/` prefers `SHOWRUNNER_REGISTRY` when set and falls back to `--show`, so the New-show form can be developed. A run whose log file does not exist answers `404 {"error":"no log for run <run> of <id>"}` (the launch window's zero-byte log still answers 200); the console has jsdom + Testing Library render tests (`console/test/client/*.test.tsx`); `initScaffold` writes `prompts/.templates-baseline.json` and `check-prompts --baseline` reports per prompt `unchanged` / `show-edited` / `template-moved` / `both` / `no-baseline` / `missing` / `no-template`; the scaffold's `.gitignore` ignores `<production>/**/*.worker.out`, `*.lock` and `*.lock.tmp`; `publish-kit.py` says the channel name is written nowhere until the key is filled; `tts-script.md` names `{{show.audio.guestRefsDir}}`; four npm advisories are closed by a root `overrides` block (total 0).
