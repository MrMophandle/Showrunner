## What the branch built

The showrunner edits a gate's markdown artifact in the browser and the gate shows the saved text at once, with one file on disk and no second copy anywhere. Three pieces make that true: a run-scoped file route (`GET`/`POST /api/shows/:show/episodes/:id/runs/:run/files/<path>`) that reads an artifact as `{text, hash}` and writes it back against that hash, refusing a file that changed underneath with 409 and the current hash, a run a live worker holds with 409, a file the open gate does not list with 403, a non-markdown or out-of-fence path with 400, and a run with no open gate with 404; an editor page at `/shows/:show/episodes/:id/runs/:run/edit/*` whose preview is the gate's own markdown renderer fed from the box as it is typed, and whose Save carries back the hash the page read; and a `file` message on the existing SSE channel that makes the gate's matching artifact pane refetch. The engine is not touched — `engine/src/provenance.ts`'s `hand-edits-outline` and `hand-edits-script` guards already treat an edited artifact as the showrunner's work, which is why editing from the console needed no engine change at all.

## What is deferred, and what it costs

**The CSS has never been rendered in a browser, and the save-to-gate round trip has never been walked by a person.** The editor's split pane, its scrollbars and the `calc(100vh - 7rem)` height in `console/src/console.css` are asserted by no test — jsdom computes no layout — and no one has opened the editor against a running console, typed into it, saved, and watched the gate's pane change. Both are to be done at the production rebuild. Cost if the CSS is wrong: the editor is ugly or unusable on the first real visit, which is a styling round and no data loss. Cost if the round trip is broken: the feature does not work at all on first use, and the tests that pass today are each proving their own half against a stub.

**The browser's Back button cannot be guarded, and is not.** The editor's "Back to the gate" link and the gate's `edit` link each call `window.confirm` before discarding typed text, and `beforeunload` covers a reload or a closed tab — but a popstate from the browser's own Back button unmounts the page silently. The fix is react-router's `useBlocker`, which exists only on a data router; `console/src/main.tsx:17-19` mounts `BrowserRouter` around `App`, whose `Routes` carry every page, so `useBlocker` is unavailable until the whole app is converted to `createBrowserRouter` plus `RouterProvider`. Cost of leaving it: a showrunner who types a paragraph into the editor and presses Back loses it with no question asked. The page's header comment states this so the next reader does not assume the guard is total.

**`rename` over a symlinked artifact replaces the symlink with a regular file.** `writeAtomically` (`console/server/artifacts.ts`) stages a sibling temp file and renames it onto the artifact's path, and POSIX `rename` replaces the *link*, not the link's target. No show repository is known to symlink an artifact today; the shape is plausible rather than observed, because the NAS mount is where finished files live and a symlink is the obvious way to put one in two places. An artifact symlinked that way would, after one save from the console, be a plain file in the show repository, and every later write by the engine or the console would land there while the NAS copy went stale with nobody told. Nothing in the code detects this and no test covers it. Cost: two files that look like one, diverging silently. The fix, if the shape ever appears, is to `realpath` the target before staging and write the temp file beside the resolved path.

**An uncaught `writeAtomically` failure reaches `app.onError` as a 500 carrying an absolute temp path.** The POST handler at `console/server/app.ts:1147` does not wrap the write, so an `EACCES`, `ENOSPC` or `ENOENT` out of `writeFile` or `rename` propagates to the catch-all at `console/server/app.ts:287`, which answers `{error: err.message}` — and that message contains the full temp path, machine root included. This is the pre-existing ruling H-14 surface and not new, but the editor makes it newly likely: the first operator to save an artifact while the NAS is unmounted after a reboot will see it. Cost: an internal filesystem path in the browser, and a refusal the operator cannot act on because it reads as a stack-trace fragment rather than a sentence.

**The `%20` round trip is asserted only at the address builders, never end to end.** `console/test/client/api-paths.test.ts` proves that `editHref` and `filePath` encode a space in a path segment as `%20` and keep the slashes as slashes, and `console/src/pages/Edit.tsx` relies on react-router handing the splat back decoded so `filePath` can re-encode it. No test drives a real file with a space in its name — `Production/<id>/images/IMAGE SHEET.md` is the live example — from the gate's link through the route to the server's fence and back. Cost: a double-encoded or half-decoded path would 400 at the fence on exactly the artifacts whose names have spaces, and the first place anyone would find out is the image sheet at a casting gate.

**A script edited at the gate and then approved reaches `publish-copy` with no reviewer having read the edit, by design.** The gate's approval is the showrunner's own judgment, and the panel's verdicts were written against the text as it stood when the panel ran; an edit made in the editor between the panel and the approval is never re-reviewed. Ryan's ruling of 2026-10-27 is that this is the point — the editor exists so a typo found at the gate does not cost a round — but the record states it plainly because the alternative reading is that the gate's green chips describe the file that shipped, and after an edit they do not. Cost: the showrunner's own change is the one change in the pipeline no reviewer sees.

## Not built

No draft is kept anywhere but the textarea: the page holds no `localStorage` copy, posts nothing on a timer, and keeps no server-side scratch file. That is what "one file, one version" means, and it is also why the three confirm paths above matter. No diff view between the box and the disk is offered when a save is refused as stale; the page offers the whole current text or nothing, and reconciling two versions is the showrunner's own job with an external tool. No editing of anything but markdown: `editableArtifact` refuses a non-`.md` path with 400, so the TTS JSON, the prompts file and the shot list are read-only at the gate.
