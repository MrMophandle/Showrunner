## What the branch built

The casting gate is a choice rather than a listening test (Ryan's ruling of 2026-10-30: "it was more 'listening to the choices' and less 'pick a choice' kinda page"). Three pieces make that true. The gate view carries a `casting` block at `casting-gate` and nowhere else — the guest-reference directory and, per guest, the manifest's cast name, the engine's `slugName` slug and the take `tts-script.json` currently casts them from (`console/server/gates.ts`'s `castingOf`, `guestRefsDirOf`). The gate's answer accepts `picks` (cast name → show-relative take), checks every one of them — a guest in the manifest, a path under the episode's guest-reference directory, an audio extension, inside the artifact fence, a regular file on disk — and rewrites the manifest atomically **before** `answerGate`, so a bad pick is a 400 with the manifest untouched and the gate still open (`console/server/artifacts.ts`'s `applyCastingPicks`). And the page draws a fieldset per guest with a radio per take, the manifest's take preselected, a sentence above Approve naming what Approve is about to cast, and the picks on the approval only (`console/src/pages/Gate.tsx`). The defect this closes is concrete: Ryan's approve note of 2026-10-30 ("approved, hallet2 and veleth2") was read by nothing, and the render that followed used whatever the manifest already said.

The engine is not touched. `tts-generate` declares `tts-script.json` as its input (`engine/src/pipelines/episode.ts:325`) and `runScriptStep` compares fresh input hashes against the last completion's, so a picked manifest emits `input_changed` instead of being served from `step_cached`. That hash trail is the only record a pick leaves.

## What is deferred, and what it costs

**A symlink inside the guest-reference directory passes the fence, and a pick can cast through it.** `resolveArtifactPath` (`console/server/artifacts.ts`) is lexical: it checks the prefix, the segments and `path.resolve`'s result against the show root, and resolves no link. `applyCastingPicks` then follows the link with `stat`, which reports the target, so a symlink at `Production/<id>/guest-refs/pim-9.wav` pointing anywhere on the machine would be accepted as a cast reference and served by the artifact route. This is **pre-existing and shared with `serveArtifact`**, which has always served a symlinked artifact's target the same way; the picker adds no new layer and removes none. No show repository is known to symlink a take, and the whole guest-refs directory is written by the showrunner recording takes. Cost: a path outside the episode's two trees can be read through a link somebody put in the show repository, and a manifest can end up casting from it. The fix, if the shape ever appears, is an `lstat` or a `realpath` check inside the fence, which belongs to the fence and to every caller of it rather than to this feature.

**`validate-manifest` is not re-run after a pick, by design, and that is checked rather than assumed.** The pipeline's order is `validate-manifest` → `casting-gate` → `tts-generate` (`engine/src/pipelines/episode.ts:319-325`), and a rejection reruns `validate-manifest` (`rerunOnReject`) while an approval does not. What that script checks about the cast is that every entry has a non-empty `ref`, `ref_text` and `direction`, and that `ref` exists on disk (`scripts/validate-manifest.py:125-128`). A pick changes `ref` and nothing else, and `applyCastingPicks` checks the new `ref` **more strictly** than the script does — inside the guest-reference directory, an audio extension, inside the artifact fence, a regular file — so re-running the script after a pick would re-prove a weaker fact. Cost: none for `ref`; the exposure is the next item, which is about a field the pick does not touch.

**`ref_text` goes stale when a pick crosses designs, and nothing validates that.** `ref_text` is the line the reference take was read from, and `direction` is the note about how. Both are written by the `tts-script` agent for the take it cast. A pick that swaps `pim-1.wav` for `pim-2.wav` — the same voice, a second read of the same line — leaves `ref_text` true. A pick that swaps two genuinely different designs for the guest (a different reader, a different line) leaves `ref_text` describing the take that was not chosen, and nothing in the pipeline compares the text to the audio: `validate-manifest` only asks that the field is non-empty. Cost: `tts-generate` is given a reference WAV and a transcript that do not match, which degrades the clone for that guest in a way that shows up only on listening to the mix. The transcript the showrunner wrote beside the take (`<slug>.txt`, shown under every radio on the page) is the information that would settle it, and nothing reads it but the operator's eyes.

**No progress message is shown while a pick is being written.** The Approve button says `approving…` and nothing else reports what the server is doing. `progressLabel` (`console/src/projections.ts:165`) renders a step's progress — count, unit, rate, ETA — from the `progress` a run's log carries, and a pick is not a step and appends nothing to the log, so there is nothing for it to render. The write itself is one small JSON file. Cost: a pick written while the NAS is unmounted, or to a show root on a slow mount, looks like a hung button for as long as the write takes, and the operator's only recourse is to wait or to reload — and a reload now asks before dropping the choice, so the wrong answer to that question costs the picks.

**The CSS has never been rendered in a browser, and the picker has never been driven by a person.** `.cast-guest`, `.cast-guest > legend` and `.cast-take` in `console/src/console.css` are asserted by no test (jsdom computes no layout), and nobody has opened a real casting gate, listened to two takes, picked one, approved, and watched `tts-generate` re-run on the changed manifest. Both are for the production rebuild. Cost if the CSS is wrong: a fieldset that reads badly on the first real visit, a styling round and no data loss. Cost if the round trip is broken: the feature does not work on first use, and the tests passing today are each proving their own half against a stub.

## Not built

No way to add a take from the console: the operator records WAVs into the guest-reference directory outside this console, and the gate lists what is there. No editing of `ref_text` or `direction` at the gate — the manifest is a read-only `json` artifact there (`editableArtifact` refuses a non-`.md` path), so the stale-`ref_text` case above is fixed by rejecting the gate and letting the fix agent rewrite the manifest. No multi-select or ranking per guest: one take is cast, which is what `cast[<guest>].ref` holds. No log event for a pick, by the pre-flight ruling below. And no picker for the non-guest cast: the narrator and the recurring cast are cast from `Production/voice-refs/refs.json` with a `LOCKED` status, which is a different decision made in a different place.
