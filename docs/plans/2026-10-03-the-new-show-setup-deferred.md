## What Plan G established that later plans build on

- **`showrunner-init`** (`tools/src/init/`, bin `tools/dist/init/main.js`): names a show and a directory, refuses a non-empty directory unless `--resume`, writes `showrunner.json` from `buildShowConfig` (every key in `SHOW_CONFIG_KEYS`; `airMap: {}`; the four directory keys always their defaults), writes the scaffold (`writeScaffold`: the house layout, the four entity templates, the outline template, the two empty reference indices, the ledger and voice-registry scaffolds, `.gitignore` derived from the config's own directory keys, the show's README rendered from `tools/templates/show/README.md`, and every prompt template), `git init`s and commits the scaffold, interviews the thirteen gated bible files in `BIBLE_FILES` order with one commit per approved file, writes the cast sheets and `audio.mainCast` after `world-overview`, runs `bible-check` as a report, creates the GitHub repository with `gh repo create <slug> --source <root> --push --<visibility>` last (or prints that command when `gh` is absent or signed out), and prints the show README's "Your first episode" section. Exit codes: 0, 1 (an error, or stdin closed — "what was written is committed; run again with --resume"), 64 (usage).
- **The interview is one engine pipeline per bible file** (`engine/src/pipelines/bible.ts`, `bibleFilePipeline`): `write` (an agent that turns `Production/setup/<key>/answers.md` into the file in the house format; prompt `tools/templates/interview/write.md`) then `gate` (message `gate.md`, fix agent `revise` with `revise.md`, `maxAttempts: 10`, `rerunOnReject: []`), or `gate` alone for the three "default" files. It runs under the **reserved episode id `setup`** (`RESERVED_EPISODE_ID`/`isReservedEpisodeId` in `engine/src/ids.ts`; `run()` and the agent executor exempt it from `parseEpisodeId`; it never matches the episode grammar, so `listEpisodeIds` never lists it), logged at `<productionDir>/setup/<key>/runs/<runId>.jsonl`, through the real executors with `promptsDir` pointed at `tools/templates/interview/`. The terminal driver (`tools/src/init/interview.ts`, `interviewFile`) asks the canon template's questions, offers a resumed file's earlier answers back as defaults, runs the pipeline, and answers the gate with approve, reject with notes (the fix agent runs and the gate reopens), "I will write this one myself" (the template without its questions is written and approved with the note "the author writes this file"), or import (a regular file, never a symlink, outside the production and canon directories, copied and approved with the note "imported from <path>").
- **Per-step template variables** (`AgentStep.vars`, `GateStep.vars`, `{{vars.<name>}}`; `GateMessageRenderer(file, ctx, vars?)`; values render through `renderValue` like `results` and `show`; `describePipeline` records them, nested steps included, with sorted keys).
- **The bible, named** (`engine/src/bible.ts`): `BIBLE_FILES` (fifteen files in interview order, each with a mode — interview, default, scaffold — and a purpose), `REQUIRED_SECTIONS` (thirty-five level-2 headings prompt templates read by name), `headingMatches` (a whole-word prefix match on normalised text, so parentheticals and suffixes are admitted; no two required headings for one file may be prefixes of each other — tested), `bibleFilesFor(show, season?)`, `missingBibleFiles`, `missingSections`. The episode pipeline's **`bible-ready` guard** sits between `previous-episode` and `premise` and fails a run by name (`BIBLE_INCOMPLETE: <list>`) when a declared bible file is absent or empty; a binding test asserts every `Canon/` input any step declares is on the guard's list. `bible-check` (`tools/dist/bible-check.js --show <root> [--season N]`) reports missing files and missing sections with their readers.
- **`SHOW_CONFIG_KEYS`** (`engine/src/show-config.ts`): sixty rows, every dotted key the engine or a script reads, with `requiredBy`, `default` where a reader supplies one in code, and `readBy`; a test greps every `sc.value`/`sc.path` site in `scripts/` (both quote styles) and refuses a key the list does not carry.
- **The generic prompt templates** (`tools/templates/prompts/`, thirty-four `.md` + eight schemas + README): the role line `You are the <role> for *{{show.showName}}*.`; `{{show.episodesDir}}`/`{{show.productionDir}}` on every line that renders a variable, `Canon/` literal; every law a prompt once stated inline is now "apply `## <Heading>` of `Canon/<file>.md`" — the house form for a section citation, both backticked — and the harness refuses a citation that is not a `REQUIRED_SECTIONS` row; config values render where the first show's values were (`{{show.visual.collectivePopulatorBans}}`, `{{show.audio.sceneTransitionGapSeconds}}`, `{{show.audio.titleCardGapSeconds}}`, `{{show.visual.auditLaws}}`, `{{show.visual.style}}`); the register is the most recently approved script under `Episodes/*/script.md` when one exists and `## Register sample` of the style guide before that. The harness (`tools/test/templates.test.ts`) renders every template against the Harbor Lights context, checks the role line, refuses history (`ep\d\d`, `2026-`, `Ryan`, hyphenated or dated "ruled") and the two cosmology words the engine grep cannot express (`vanished`, `dark forest`), and checks every `Canon/` reference and section citation.
- **The bible templates** (`tools/templates/canon/<key>.md`): level-2 headings are the file's sections and an HTML comment `<!-- Q: … -->` after a heading is its interview question (one or two sentences; at most one Harbor Lights example); `parseCanonTemplate` and `templateWithoutQuestions` in `tools/src/init/scaffold.ts`. Every law the interview writes is stamped `DRAFT (interview <date>)` and the interviewed files carry the RULED/DRAFT legend. Three house documents are filled defaults the author keeps, edits or replaces at their gate: `story-craft.md`, `pipeline-artifacts.md` (its show-facing part), `Canon/README.md`.
- **The show-name rule now covers `tools/templates/`** (it was always inside the grep's paths); the invented show for every fixture and example is "Harbor Lights" (slug `HarborLights`; cast Vale, the Warden, Pim, Maeve; location Harbor).

## Plan H — the console side of the new-show setup (Ryan's ruling, 2026-10-03)

- **A show registry over `--show`** (one server, many shows; Plan E's O-05). `ShowContext` takes one root and nothing else assumes a single show; the registry touches `ShowContext`, `RunStore` (one watcher per show), the worker's argv, and every route's notion of which show it means.
- **The "New show" surface over `init`** (spec §9.4; the inventory's F-25). What `init` already produces for it: an absolute root and a config that loads; `runInit(opts, io, deps)` takes an `InitIO` the console can implement over a form and a WebSocket or SSE stream, and `InitReport` carries the files, commits, remote and `stalled` list.
- **The interview's runs in the console.** They live under `Production/setup/<key>/runs/` with the reserved id `setup`, which the Board never lists; Plan H decides whether a show's setup runs appear (a "Bible" view over `BIBLE_FILES` with each file's latest run status and gate).
- **The `init` IO on a real terminal.** Every test drives a pipe; the IO prints its own `> ` prompt and reads stdin through a line queue, so readline's line editing applies to the line being typed but no test has run on a TTY. Plan H's surface replaces the terminal IO for the console path; the terminal path is checked at the first real `init`.

## The first real `init`

- **The writer's fidelity over fourteen files.** One cooperative sample (Task 9's `world-overview`, nine answers, claude-fable-5) invented nothing; a blank answer, a one-word answer and two contradicting answers are untested, and the exercise fakes the writer. The first full interview is the measurement.
- **Cost.** $2.24 for one file on the writer model, so a thirteen-file setup is near $30 before the author writes a premise. `models.medium` is untested for fidelity; Ryan's import path costs nothing.
- **Ten attempts** as the cap for a bible gate (the episode gates' number); a file rejected ten times is kept as last revised, listed in `InitReport.stalled`, and finished by hand or with `--resume`.
- **The `DRAFT (interview <date>)` stamp** is the local date since the fix wave (it was UTC: an interview at 21:00 Pacific on 2026-10-03 was stamped 2026-10-04); an interview that spans midnight stamps two dates across one bible.
- **A cast name's capitalisation** can drift between the prose bullet the writer produces and `audio.mainCast` ("The Warden" / "the Warden"); nothing machine-read breaks today.
- **A non-Latin-script cast name** (`山田`) is refused by `slugOf`'s backstop with a message about alphanumerics; transliteration or an explicit slug belongs with the interview that collects the name. Accented names (`Maève`) are accepted (the directory keeps the accent, the file name drops it).
- **`gh repo create`** against an account that already has a repository of that name; the repository lands under the authenticating user (no organisation flag); `init` needs a git identity (`user.name`/`user.email`) and fails at the scaffold commit with git's message otherwise; `init` does not check that the NAS root is mounted.
- **`mintRunId`'s four random characters** make two ids minted in one second sort arbitrarily, and `isApproved` and `priorLogs` depend on lexical order; a crash resumed inside the same second could read the crashed log as the latest. The fix belongs to `engine/src/runs.ts`.
- **`gitCommit`** uses `git commit --only -F - -- <paths>` since the fix wave, so work an author staged before running `init` is never swept into a bible commit; `--resume` makes the scaffold commit when the repository has no `HEAD`.
- **`resolveRoot` resolves only the immediate missing parent** of a `--path` that does not exist; two or more missing levels under a symlinked ancestor keep the symlink unresolved.
