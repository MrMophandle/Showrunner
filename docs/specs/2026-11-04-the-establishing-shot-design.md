# The establishing shot — one image per scene, every image by nano-banana — design

**Date:** 2026-11-04. **Status:** design approved in chat by Ryan on 2026-11-04 ("design stands, write the spec and rerun the image creation for s02e01"). **Supersedes:** the image stage of the episode pipeline as it stood at Showrunner `main` 407442f and on branch `cast-index` (PR #123), and the face half of `docs/specs/2026-10-31-the-casting-stop-design.md` §1 where that spec demands a face for everybody on the page.

## 0 · What this is

The engine makes **one image per scene**, an establishing shot that sets the listener in the place of that scene, and **every image is rendered by nano-banana** (Gemini `gemini-3-pro-image`). The local image renderer (Z-Image through mflux) is removed from the engine, together with the ambient/character split, the populator loop that guarded the local renderer, and the second image gate that existed to approve paid shots before more were spent. Ryan keeps the ability to add shots to any scene by hand, and the engine never authors a character shot on its own.

Dead Light is a story channel, not a visual one. s02e01's shot list under the old rule was 47 images (15 character, 32 ambient); under this spec it is 12.

## 1 · Rulings this spec implements

- **2026-11-04 (Ryan):** "This youtube channel wasn't supposed to be more visual than story. I'm completely ok with limiting images to one per scene. I will always want the ability to add more to a scene, but I think the engine should only focus on capturing an establishing shot for each scene, something that sets the listener in the area of the scene."
- **2026-11-04 (Ryan):** "I want to use Nano Banana for these establishing shots. No more local image development. It was always hit or miss. Lets dismantle the local image creation portion of the engine."
- **2026-11-01 (Ryan):** character reference images are generated by nano-banana, never by Qwen-Image, and N candidates are N distinct briefs, not N seeds of one brief (recorded in the casting-stop spec's change log). This spec carries the face designer onto the same renderer.
- **Standing (DeadLight PR #10, 2026-10-29):** a scene is a location. One establishing shot per scene is therefore one image per location change.

## 2 · The shot list

**2.1 One shot per scene.** `Production/<episodeId>/images/prompts.json` holds exactly one `establishing` shot for every scene header in the script (`## COLD OPEN`, then `## SCENE <N> — <name>` in order), with the id `s<n>-establishing`, where `<n>` is the scene's ordinal (the cold open is 1). No count rule, no budget, no weighting: the script's scenes are the count.

**2.2 The shape.** The local renderer's fields (`prompt`, `seed`) are gone; every shot carries a `brief`.

```json
{ "episode": "s02e01",
  "shots": [
    { "id": "s01-establishing", "scene": "COLD OPEN", "type": "establishing", "source": "pipeline",
      "brief": "<the place at this scene's hour and light, in positive description>",
      "width": 1024, "height": 576 },
    { "id": "s04-sarn-at-the-board", "scene": "SCENE FOUR — THE ARGUMENT WORSENS", "type": "character",
      "source": "showrunner", "brief": "<what the shot shows>", "refs": ["sarn"], "width": 1024, "height": 576 }
  ] }
```

- `type` is `establishing` or `character`. The engine writes only `establishing`. A `character` shot exists only because Ryan asked for it (§2.4).
- `source` is `pipeline` (nano-banana renders it) or `showrunner` (Ryan makes it by hand and drops the PNG in; nothing renders it and the `showrunner-images` guard waits for the file).
- `refs` is required on a `character` shot and forbidden on an `establishing` shot. Each ref is a cast-index key whose entry has a `face.ref` on disk.
- `width`/`height` default to `visual.shotFrame`.

**2.3 The establishing brief.** A wide view that sets the listener in the place: where it is, the hour and the light, the weather or atmosphere, the scale cues (a gantry, a hull, a table) and the one or two objects the scene turns on. It names **no character of the cast, no creature, no species**, and asks for no legible text. Human figures, if the place needs them, are distant and faceless. Positive description only (the show's negation law stands). The style constants (`visual.styleConstants`) are appended by the renderer, not written into the brief.

**2.4 Adding more to a scene.** Ryan adds a shot in one of two ways, and both are the existing mechanism:

- At the image gate, a rejection note that names the scene and the shot ("scene four: add Sarn at the board, refs sarn") is folded into `prompts.json` by the image-gate fix agent as a `character` shot with `source: "pipeline"`, and nano-banana renders it conditioned on the named references, exactly as character shots render today.
- By hand: a shot entry with `source: "showrunner"` and the PNG dropped into `images/` under that id. The guard after the gate holds the run until the file exists.

A console affordance for this (a form on the image gate) is not built here (§11).

**2.5 The lint: `shot-list-check.py`.** Replaces `populator-check.py`. Reads the script and `prompts.json`, prints a table and one tag, `SHOTS_OK` (exit 0) or `SHOTS_BAD` (exit 2 with `--report-only` printing the reasons and exiting 0, the same contract `populator-check` had, so the fix loop can read the tag from the step's result). Rules, each with a one-line reason naming the shot:

1. One `establishing` shot per scene header, ids `s<n>-establishing` in header order; a scene with none, a shot for a scene the script lacks, or two for one scene is BAD.
2. An `establishing` brief names no cast-index entry (whole-word match on the entry's `name` and key, `the` stripped) and no entry of kind `species`.
3. A `character` shot has at least one ref; every ref is a cast-index key whose `face.ref` exists on disk. The reason names the key and the remedy ("cast the face, or set source to showrunner").
4. Every shot: unique `id`, `scene` equal to a header, `type` in {establishing, character}, `source` in {pipeline, showrunner}, non-empty `brief`.
5. The keys `prompt` and `seed` are absent ("the local renderer is gone; write a brief").

The loop keeps the populator loop's shape: `shot-list-check` (report-only) → `visual-direction-fix` (an agent, when the tag is BAD) → `shot-list-check-final` (when the first was BAD; a second BAD fails the run with the reasons).

## 3 · One renderer

**3.1 `scripts/lib/nanobanana.py`.** The Gemini client lifted out of `nano-banana-generate.py` so two callers share it: the key check and its setup text, the client, reference-image encoding, the API call with its retry and client-error classification, the JPEG-to-PNG workaround, the refusal diagnostic, the atomic write, the key redaction, and the one-line remedy for HTTP 402 ("Google AI Studio credits are depleted — top up at https://ai.studio/projects"). No behaviour changes in the move.

**3.2 `nano-banana-generate.py` renders every pipeline shot.** The filter `type == "character"` goes: every shot with `source: "pipeline"` and no PNG on disk is rendered. An `establishing` shot's prompt is its brief plus the style constants, with no reference images. A `character` shot's prompt is the identity lines for its refs plus the brief plus the style constants, conditioned on each ref's reference image and gallery, as today. `--only <id,id>` re-rolls named shots. Result tags unchanged: `NANO_OK n/n` or `NANO_PARTIAL k/n` (both exit 0; the gate and the audit read the files). Progress is per shot.

**3.3 `design-visual.py` renders faces by nano-banana from briefs.** `design-visual.py <key> --briefs <file> [--show-root <path>]`: the file holds N briefs (a JSON list of strings); one nano-banana call per brief, text only, into `<visual.candidatesDir>/<key>-<n>.png`; the script prints the lock path as it does today. The Qwen-Image path and the per-subject seed are deleted. `baseline_prompt` in the index stays as the brief author's starting point, not as the prompt.

**3.4 Removed.** `scripts/image-generate.py` (Z-Image), `scripts/populator-check.py`, `scripts/image-qc.py` (an advisory histogram screen the pipeline does not call), `scripts/lib/populators.py` if nothing but the two deleted scripts reads it, their tests, and every mention of Z-Image, mflux, "ambient", "local GPU" and "populator" in `engine/`, `scripts/`, `tools/` and `console/`. The scripts package declares no mflux dependency (the old scripts called the binaries by name), so nothing leaves `pyproject.toml`. Ryan's Qwen-Image model caches under `~/.cache/huggingface/hub/` are his to delete.

## 4 · The image stage

Steps, in order, from the audio gate:

| step | kind | what |
|---|---|---|
| `visual-direction` | agent | writes `prompts.json`: one establishing shot per scene (§2) |
| `shot-list-check` | script | the lint, report-only |
| `visual-direction-fix` | agent | when BAD: repairs the list against the reasons |
| `shot-list-check-final` | script | when the first was BAD: a second BAD fails the run |
| `nano-banana-generate` | script | renders every pipeline shot without a PNG |
| `image-audit-1` | agent | the vision audit against the audit laws; a failing shot's brief is rewritten and its PNG deleted |
| `image-regenerate-1` | script | when audit 1 failed: `nano-banana-generate.py` again (renders what is missing) |
| `image-audit-2`, `image-regenerate-2`, `image-audit-3` | | the same, twice more |
| `image-audit-verdict` | guard | passes on the last audit's verdict; fails with "images still failing after 3 audits" |
| `image-sheet` | script | writes `IMAGE-SHEET.md`: the shots in scene order, each with its state (rendered, by hand and present, by hand and missing) |
| `image-gate` | gate | the one image gate (§4.1) |
| `showrunner-images` | guard | every `source: "showrunner"` shot has its PNG |
| `image-sheet-final` | script | the sheet as approved |

Removed: `populator-check`, `populator-check-final`, `image-generate`, `nano-banana-gate` and its fix agent. The audit's re-rolls go through nano-banana (each re-roll is a paid call; the loop is capped at two re-roll rounds, as today). The timeline builder is unchanged: a scene's one shot holds across the scene.

**4.1 The image gate.** Message: the sheet's path, the auditor's last summary, and the rule for notes. Approve, or reject with notes naming shots: "s03-establishing: too bright, it is the night watch" re-rolls that shot with the note folded into its brief; "scene four: add Sarn at the board, refs sarn" adds a character shot; "I'll make s07 myself" sets that shot's `source` to `showrunner`. The fix agent (`image-gate-fix`, `image-gate.reject.md`) edits `prompts.json` and deletes the PNGs to re-roll; `rerunOnReject` is `["nano-banana-generate"]`, so the audit loop runs again on the regenerated set. `maxAttempts` 5, as today.

## 7 · The probe

`refs-ready` (`engine/src/needs.ts`, `missingRefs`) no longer demands a face for anybody. It demands, for everybody the outline tags `speaks`, a LOCKED voice with its WAV on disk, as Plan L1 left it. The face requirement moves to the lint (§2.5 rule 3), where a shot that needs a face is known. This supersedes the casting-stop spec §1's "a face for everybody on the page" and §2's `casting-needs` guard as far as faces go: Plan L2's casting stop casts a voice for every new speaker and a face only when Ryan asks for a character shot of them, which is a change to that spec to be made when L2 is planned.

## 8 · Console

`console/server/gates.ts` drops the `nano-banana-gate` case; the `image-gate` case lists the images directory and the sheet. The stage map in `episode.ts` drops the gate. The contact sheet's re-roll flags are unchanged. Tests that pin the pipeline's step count move to the new count.

## 9 · Cost and time

Twelve to fifteen nano-banana calls per episode, plus re-rolls (at most two rounds, each re-rolling only the shots the audit failed), from Ryan's Google AI Studio credits at that model's per-image price; about a minute of wall-clock per shot. No local GPU time.
