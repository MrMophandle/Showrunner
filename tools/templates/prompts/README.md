# prompts/

This directory holds every agent prompt the show's pipeline runs, one prompt per file.
These prompts are the show's asset, not the engine's: they are written and edited here, in the show repository, and the engine at `~/GitHub/Showrunner` reads them by file name and never contains their text.
The naming scheme is `<step>.md` for a step's prompt (a standalone agent node or a loop body), `<gate>.gate.md` for the message a gate shows the showrunner, `<gate>.reject.md` for the prompt that runs when the showrunner rejects that gate, and `<step>.schema.json` for the JSON shape that step's output must have.
A file's basename is the id of the step that reads it, so step ids must stay unique across this whole directory; nothing is prefixed by workflow.
Every prompt's first line, gate messages excepted, declares the agent's role and the show: `You are the <role> for *{{show.showName}}*.` A hand-written prompt follows the same line so the set reads as one.
The template variables are `{{episodeId}}`, `{{runId}}`, `{{showRoot}}`, `{{season}}` (the numeric season, unpadded), `{{show.<path>}}` (a dotted path into `../showrunner.json`, such as `{{show.video.fps}}`), `{{vars.<name>}}` (one of the step's own variables, a flat name and never a path, so one prompt file can be run for several targets), `{{results.<stepId>}}` and `{{results.<stepId>.<field>}}` (an earlier step's result), `{{results.<gateId>:rejection}}` (the showrunner's rejection notes, which resolve only inside a `*.reject.md`), and `{{results.<gateId>:rejections}}` (the run-wide array of every note that gate has received so far, in order — a JSON list, empty before the first rejection — which any step's prompt may render, not only that gate's, and which both canon-reviewer prompts do).
Every variable must resolve: the renderer treats an unknown name, a missing step result, or a null value as an error rather than rendering an empty string, because a prompt with a hole in it lies to the model quietly.

Two conventions written by these prompts are read by machine rather than by a person, so a change to either breaks the pipeline and not merely a prompt.
**The outline's `## Cast` section is the pipeline's NEEDS_REFS source**: every line in it reads `- <Name> (<tags>)`, tags drawn from `recurring`, `guest`, `speaks` and `location`, and `parseCastSection` in the engine's `engine/src/needs.ts` silently ignores any line in the section that does not match that grammar.
**The shot list's `source` field is the pipeline's NEEDS_IMAGES source**: each shot in `Production/<episodeId>/images/prompts.json` is `"pipeline"` (the default, and what the generators make) or `"showrunner"` (a shot the showrunner makes by hand, which no generator touches and which holds the run at NEEDS_IMAGES until its PNG is on disk).
To check the directory after editing it, run `node tools/dist/check-prompts.js --prompts <this directory> --context <a sample context>` from `~/GitHub/Showrunner`, which renders every `.md` in it except `README.md` against a sample context and names any prompt with a hole in it.
`README.md` is the one file the checker skips: it quotes the variable forms rather than using them, so checking it would report a hole in the file that is meant to contain one, and nothing renders it at run time.
